# Stage 1: server

Use Node 20 (`nvm install && nvm use`), then `npm ci`.
Run `npm run typecheck`, `npm test`, and `npm run build`.
Start the built server with `npm start`; it serves the placeholder web app.
The tests use in-memory fakes and never contact Google.

## Configuration

Set these environment variables in Cloud Run (use Secret Manager for secrets):

| Variable             | Value                                                            |
| -------------------- | ---------------------------------------------------------------- |
| GOOGLE_CLOUD_PROJECT | Google Cloud project ID                                          |
| GCP_LOCATION         | Vertex region, default us-central1                               |
| GEMINI_MODEL         | Default gemini-2.5-flash                                         |
| OWNER_EMAIL          | Owner's personal Gmail address                                   |
| OAUTH_CLIENT_ID      | Google web OAuth client ID, also the dashboard ID-token audience |
| OAUTH_CLIENT_SECRET  | OAuth secret; also signs short-lived Gmail OAuth state           |
| EXTENSION_API_KEY    | Random secret of at least 24 characters                          |
| PUBLIC_URL           | Cloud Run HTTPS URL, no trailing slash                           |
| PUBSUB_TOPIC         | projects/PROJECT/topics/TOPIC                                    |
| PUSH_SERVICE_ACCOUNT | Service account email expected on push and Scheduler tokens      |
| GHOSTED_AFTER_DAYS   | Positive number, default 45                                      |
| PORT                 | Default 8080 (Cloud Run sets this)                               |

For local development use Application Default Credentials (`gcloud auth application-default login`).
Never commit credentials or refresh tokens. Firestore stores refresh tokens in
`config/gmail`; restrict database IAM to the runtime service account and operators.
Do not enable public Firestore client access.

## Google Cloud prerequisites

1. Enable Cloud Run, Artifact Registry, Firestore, Vertex AI, Gmail API, Pub/Sub,
   Cloud Scheduler and Secret Manager. Create a Firestore Native database.
2. Give the runtime service account Firestore user and Vertex AI user permissions,
   plus access to the necessary secrets. Build the root Dockerfile and deploy it
   to Cloud Run. The service must accept unauthenticated ingress because the OAuth
   callback and static dashboard are public; application endpoints enforce their own auth.
3. Create an external OAuth consent screen and a web OAuth client. Add the owner as
   a test user while testing. Authorized redirect URI:
   `PUBLIC_URL/auth/gmail/callback`. Add the dashboard origin as an authorized JS
   origin for Google Identity Services in the later dashboard stage.
   Gmail readonly is a restricted scope. In OAuth testing mode refresh tokens may
   expire after seven days; production publishing/Google verification requirements
   must be addressed before relying on long-lived unattended operation.
4. Create the Pub/Sub topic and grant
   `gmail-api-push@system.gserviceaccount.com` Pub/Sub Publisher on it.
   Add a push subscription to `PUBLIC_URL/pubsub/gmail`, using
   PUSH_SERVICE_ACCOUNT and the exact endpoint URL as OIDC audience.
   Grant the Pub/Sub service agent permission to mint that account's OIDC tokens.
   Configure retries and a dead-letter topic for persistent transient failures.
5. Create a daily Cloud Scheduler POST to `PUBLIC_URL/tasks/daily`, using the
   same account and the exact tasks URL as OIDC audience.
6. Call `POST /api/gmail/connect` with the owner's Google ID token and open its
   returned URL in the same browser (the callback verifies a signed state and
   HttpOnly cookie). Only the configured owner's mailbox can be connected.

Dashboard API calls use `Authorization: Bearer GOOGLE_ID_TOKEN`.
Capture uses `X-API-Key`. No CORS access is enabled: the future dashboard is
same-origin, while the extension will use Chrome host permissions.

## API and storage notes

Capture accepts `{url,pageTitle,text}`; extraction sees at most 40,000 characters.
Application PATCH accepts editable job fields, status, appliedAt and lastActivityAt.
IDs, creation/update timestamps, and event history are server-managed.
Review resolve accepts apply/create/dismiss actions described in the project brief.
All stored dates generated by the server are ISO strings.
Salary values may be null if extraction cannot provide them.
Events retain subject, sender, snippet (300 characters) and Gmail link, never full
email bodies. Bodies are sent to Vertex for classification, not persisted or logged.
The email date is retained on review items.

Matching uses exact job ID first, otherwise normalized company/sender plus title
token Jaccard. Multiple applications require similarity >= 0.6 and a margin >= 0.2.
Ambiguous job IDs go to review. Withdrawn applications are excluded.
Firestore transactions serialize application/review mutations and dedupe capture.
For this single-owner app, those transactions read the small application/review
collections; this is not designed for large multi-tenant datasets.
Gmail event/review writes are idempotent before the processed marker is saved.
History cursors never move backward. Each successfully processed notification saves
lastSyncAt. Expired history only queries after that timestamp; without a timestamp,
it resets to the notification cursor without processing any older messages.

Permanent Gmail notification errors are acknowledged and need operator attention;
transient failures return 503 for Pub/Sub retry. Monitor Cloud Run errors and the
Gmail watch expiration. No cloud resources are provisioned by this scaffold.

## Dashboard and extension

The built React dashboard is served by the server at /. It fetches the public
OAuth client ID from /config.json, then uses Google Identity Services. Add your
Cloud Run origin (and http://localhost:8080 for local use) to the OAuth client's
authorized JavaScript origins. ID tokens stay in sessionStorage and are cleared
on sign-out or a 401 response. Use the owner's account.

The Applications tab supports status filters, company/title search, editing, and
deleting applications. System-managed record IDs, timestamps and timeline entries
are shown for reference rather than editable. Applied/last-activity dates are editable.
Needs review lets you apply an email to a suggested application, create a new one,
or dismiss it. Settings connects Gmail.

Load the extension/ folder unpacked; see ../extension/README.md.
Run npm run format to format source with Prettier (single quotes, 100 columns).
